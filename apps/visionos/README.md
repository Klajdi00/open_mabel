# apps/visionos — Vision Pro teleoperation app

A visionOS app for whole-body teleoperation of MABEL from one Apple Vision Pro, with no
hand-held controllers. The headset streams head pose and both 27-joint hand skeletons to the
teleop gateway, which retargets them to the arms, ORCA hands, neck, torso, lift and base. The
app shows the stereo head cameras, wrist cameras and a live 3-D mirror of the robot.

It is a client of the same wire contract as every other command source
(`server/wire_protocol.py`, WebSocket `:9090`), so every command passes the `controller/`
safety gate. It works the same against the real robot and the MuJoCo twin.

**Features:** immersive teleop (arms only / upper body / whole body), true-scale stereo head
window, base and lift drive pad, 3-D robot space with sensor layers and navigation goals,
shared e-stop and torque state (arms start limp), operator calibration, an autonomy timeline
editor, and an on-device demo (`DemoLink`) when no robot is connected.

## Build and run

Requires Xcode with the visionOS SDK (deployment target visionOS 26.4), a Vision Pro for
tracking (the Simulator runs UI and networking only), and a running gateway: `bash
server/run.sh` (simulation) or `bash server/real_run.sh` (real robot).

1. `open apps/visionos/MabelTeleop.xcodeproj`
2. In *Signing & Capabilities* choose your own team and change the bundle identifiers
   (`org.example.MabelTeleop-V2`, `…-V2Tests`) to your namespace.
3. Run the **MabelTeleop** scheme on your Vision Pro.

Tests (no robot or headset needed):

```bash
cd apps/visionos
xcodebuild test -project MabelTeleop.xcodeproj -scheme MabelTeleop \
  -destination 'platform=visionOS Simulator,name=Apple Vision Pro'
```

## Connecting to a robot

Each known robot (Settings) can have several routes; the app races them with a TCP probe and
uses the fastest that answers. Moving to a better route is automatic; dropping from a network
route to Bluetooth asks first.

| Route | How it is found |
|---|---|
| Wi-Fi LAN | Bonjour `_mabel-teleop._tcp` (advertised by the gateway), or a host added by hand |
| Tailscale | the robot host's `100.x.y.z` tailnet address, added by hand |
| Bluetooth LE | `server/ble_bridge.py` on the robot; control and telemetry only, no video |

Add a robot: Settings → **Add robot**, with a name and a host or IP (e.g. `192.168.1.42` or a
`100.x` Tailscale address). If the robot host runs with `MABEL_TOKEN` set, enter the same code
as the real-robot access code (stored in the Keychain). The compiled-in example hosts are in
`MabelTeleop/Services/NetworkConfig.swift`; replace them with your own.

## Interfaces

| Port | Protocol | Use |
|---|---|---|
| 9090 | WebSocket `/teleop` | `hello`, `teleop_frame`, `robot_state`, `ping`/`pong` ([protocol](../../server/docs/protocol.md)) |
| 8080 | HTTP | MJPEG `/camera/<name>/stream.mjpg` |
| 9091 / 9092 | UDP | JPEG / H.264 video (latest frame wins) |
| 9092 | WebSocket `/map` | live SLAM map |
| 9610 | WebSocket | voice |

`teleop_frame` transforms are 4×4 row-major in ARKit's world frame (+Y up, −Z forward); hand
joints are relative to the hand anchor. `robot_state.jointPositions` is absolute MuJoCo
`qpos`; the app renders `qpos − ref` (`ref` from `rig.json`).

## Layout

`MabelTeleop/` — `Features/` (Teleop, Robot, Body, Navigate, Autonomy, Settings, …),
`Services/` (RobotController, WebSocketLink, BLE, ConnectionPlanner, RobotStore,
NetworkConfig), `Networking/` (wire, MJPEG/UDP/H.264 video), `Tracking/` (ARKit),
`Visualization/`, `Resources/MabelRig/` (generated by `simulation/tools/glb_to_rig.py`; do not
edit). `MabelTeleopTests/` is the XCTest suite; `mabel-server/` and `mabel-client/` are local
protocol and camera stubs; `scripts/exp_retarget_latency.py` measures wire-level retargeting
latency against a local gateway (`bash server/start_teleop.sh`).
