# Data Curation studio

A browser tool for inspecting, scoring and editing MABEL episodes (`episode_XXXX.h5`) and
exporting them to LeRobot. It reads the HDF5 files the collectors write, plays every recorded
stream in sync (cameras, LiDAR, joints, commands, poses), poses the robot in 3-D inside the
map built from its own LiDAR, flags data defects, and lets you trim, cut, merge and reorder
episodes non-destructively before export.

```text
data_curation/
├── server/          FastAPI backend: HDF5 reader, video/LiDAR/scene endpoints, quality engine,
│                    EDL validate/preview/materialize, LeRobot export, sample-data generation
│   └── tools/       experiments behind the report figures + headless-browser smoke tests
├── web/             vanilla ES-module + three.js frontend (no build step)
└── docs/            data_studio.pdf (design and measured timing/recovery results) + figures/
```

## Run

```bash
cd learning
python3 -m data_curation.server          # http://127.0.0.1:8093
```

| Variable | Default | Meaning |
|---|---|---|
| `MABEL_DATASET_ROOT` | `imitation_learning/data_collection/datasets` | folder of datasets (one subfolder per dataset, `episode_XXXX.h5` inside) |
| `MABEL_STUDIO_WORKSPACE` | `data_curation/workspace` | edit projects and transcode cache; never inside the dataset root |
| `MABEL_STUDIO_PORT` / `MABEL_STUDIO_HOST` | `8093` / `127.0.0.1` | bind address |

To review real-robot sessions, point the root at the collector's output, e.g.
`MABEL_DATASET_ROOT=../real/vision_os`.

With no data, use **Generate Data** in the UI, or generate simulated sample episodes from the
command line (the `PYTHONPATH` entry makes the sibling collection package importable):

```bash
cd learning
PYTHONPATH=imitation_learning python3 -m data_curation.server.sampledata \
    --name studio_sample --episodes 3 --frames 120
```

The 3-D viewport loads the robot rig (`mabel_rig.glb`, `mabel_joints.json`) from
`web_gui/shared_assets/` (regenerated by step 2 of the model pipeline,
`ros/src/mabel_description/urdf_to_glb.py`).

## Interface

| Region | Content |
|---|---|
| Library (left) | datasets and episode cards (thumbnail, task, frames, curation status) |
| 3-D viewport | the robot posed from `obs/joint_pos` and the chassis pose, inside the accumulated LiDAR map; toggles for map, live scan, TF frames, end-effector ghosts, grid |
| Video wall | any subset of the seven cameras, frame-accurate to the playhead |
| Topics / Info (right) | tree of recorded streams; per-episode metadata and quality |
| Joint state | measured vs. target for all 59 actuators; click a bar for its time series |
| Timeline (bottom) | trim, blade (`B`), ripple-delete (`Backspace`), merge (`Cmd+J`), reorder, snap, zoom, Save Episode |

Keyboard: `Space` play/pause, `J K L` reverse/stop/forward, arrow keys step, `B` blade,
`Backspace` ripple-delete, `Cmd+J` merge, `S` snap, `+/-` zoom, `Shift+Z` fit, `Cmd+S` save,
`Esc` deselect.

## Editing model

A timeline is an edit decision list (EDL): an ordered list of `(dataset, episode, start, end)`
segments. Every edit is a pure transform on that list; source `.h5` files are never modified.
Saving materializes the EDL into a new `episode_XXXX.h5`, slicing and concatenating every key
(including JPEG blobs) and rebasing `time/*` to be monotonic. Edit projects are stored as
`<name>.edl.json` in the workspace.

## Quality engine

`server/quality.py` works on the raw HDF5 with NumPy only:

- **Command-to-motion lag**: cross-correlates the motion energy of `action/ctrl` against
  `obs/joint_vel` (and `teleop/base_cmd` against `obs/base_twist` when the base is driven).
  A systematic lag pairs observations with the wrong action at training time; it can be
  corrected per clip and is gated at export.
- **Timing gaps**: inter-frame intervals of `time/wall` against the episode's own median cadence.
- **Defects**: frozen motors (command changes, position does not), torque-dead joints, camera
  freeze or blackout, and low or changing effective rate.

## Export

The studio exports either edited episodes (`/api/export/episodes`) or a LeRobot dataset
(`/api/export/lerobot/dataset`). The headless equivalent used in the learning pipeline is
[`../curate_export.py`](../curate_export.py); see [`../PIPELINE.md`](../PIPELINE.md).

## Robot mapping

Episodes store 59 actuator values; the rig has 60 named joints. `server/joint_map.py` maps
them by name normalization (`"Left Arm 1"` → `left_arm_1`) with one special case: `Lift` drives
`lift_lower` and `lift_upper`, each at half the value.

## Reproducing the report figures

```bash
cd learning
python3 -m data_curation.server.tools.exp_sync            # injected command-skew recovery
python3 -m data_curation.server.tools.exp_align           # camera-to-proprio alignment recovery
python3 -m data_curation.server.tools.make_imperfect --n 6  # episodes with injected defects -> 'imperfect_sim'
python3 -m data_curation.server.tools.exp_robustness      # defect-detector recall on 'imperfect_sim'
```

These need at least one episode in the dataset root (generate sample data first). Figures
are written to `docs/figures/` (`sync_recovery.pdf`, `align_recovery.pdf`, `robustness.pdf`).
